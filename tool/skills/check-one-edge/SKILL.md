---
name: check-one-edge
description: After the pieces of a module were checked alone, find what the module stores in ONE clock edge from each control state, with its executable Python translation. The result is a measured table (control state before the edge, next value of each control register, which piece's result each data register takes and with which parameter) and a check that the pieces, computed together in one edge, still give what they give alone. Later orders build the whole operation from this table.
---
Principle. Reading gives a hypothesis; running gives a fact. One edge is the smallest thing a clocked design does: from the registers before the edge and the inputs, every register gets its next value. The table of this skill is filled from runs of one edge, with your own Python scripts. Nothing is run from reset here, and no whole operation is run; that comes later and is built from this table.

Tools for your scripts (library sigdump, read the text at its top): `sigdump.step_once(model, inputs, state)` runs one edge from a state you choose and returns every signal before and after it; `sigdump.same_as(rec, name)` names the signals that hold the value a register took; `sigdump.edge_table(rec)` prints one edge. The model's values are `V` (library svvec).

1. Registers and cases. Work on the class of the module of the scope, driven at its own ports (for a module below the top: its own class, with its ports given to sigdump as `interface=`; read them from its source). From the translation (rtl_model.py) list the registers of the scope (what `step` writes at its end) and separate them: control registers (counters, states, flags) and data registers. For each register read the statement that chooses its next value and list the conditions it tests. A case is one combination of these conditions: every branch of every choice is in at least one case, and so are the first value of a counter, its last value, and the value after the last (for a register of which the source tests single bits: each tested bit set, and the bit after it). A condition that comes from a unit below is set through that unit's register. Give each case a short name.

2. One edge per case. For each case: a new model with all switches of the earlier orders on, the control registers set to the case, the data registers and the inputs set to random known values (keep them in the script), one edge with `step_once`. Run each case with two different random data values. From the records write for the case:
   - each control register: value before, value after;
   - each data register: kept its value, or took the value of which signal (`same_as`); when no signal has the value, find by a run what it took (an input in another arrangement, a part of a signal). A wide register that the source builds from parts is taken part by part (`same_parts`): each part kept, or took which signal or which other part;
   - the parameter the stored result was computed with (which round, index, part of a table or key): show it by a run, for example by changing only that part of the state and seeing the result change, or with the ranges svvec records for the line.

3. The pieces together in this edge. For each case in which a data register takes the result of a chain of pieces: take from the record the value every piece has after the edge, and compute the same chain with the references of the pieces (those of the earlier order, each already compared with its piece alone), the first from the register values before the edge, each next one from the value the piece before has IN THE RECORD. Compare each reference's result with the piece's value in the record, every element.
   - Do this on a new model (signals from no earlier edge) and on a model that has run another edge before with other data. A piece whose value in the record depends on the edge before does not compute from the values of this edge: a statement reads a signal before the statement that writes it in the same pass (skill sv-semantics). An X where the inputs of this edge are known has one of two causes: such a read before the write, or a select outside its vector (a parameter outside its range, point 4); print the operands to see which.
   - A piece that a switch makes not apply in a named control state is written as "not applied in this state" and is not compared with its reference there.
   - The first piece of the chain that differs is the place. Find the statement and the operand as in the skill check-pieces-against-spec (first wrong element, operand table), and prove it with a switch that changes this one place. With the switch on, the chain agrees in every case.

4. The table. One row per case: the control state before; each control register after; each data register: kept, or the piece whose result it takes and the parameter; the pieces of the chain: agree or differ (point 3). Under the table list the rows that need a judgement which one edge cannot give, without judging them: a data register that changes in a state in which the design waits, is idle or has finished; a control register that moves without a start; a parameter outside its range; a value that is stored from a piece that has X; a value of a control register that the handshake needs (for example the one that signals the end) and that no row gives as a next value; a state that no row leads to. The order that walks the whole unit judges these with the specification.

5. Report: the cases, the table, the list under it, each switch of point 3 with the source file, line and change and the values without and with it, and the script that fills the table (a later order runs it again and reads the table from it: make it print the table from runs, with all switches that are on at the time, and give it a function that returns for a control state and the inputs: for each data register (or each part of it) "kept", "load", or the ordered list of (piece, parameter) of the chain whose result it takes. The order of the pieces of the chain is written once in the script as a list, read from step(). The function measures by runs with two data values: which signal the register took (`same_as`, `same_parts`), the parameter (change one part of the state), and for every piece of the list whether it is applied in this state (`sigdump.applied`): a piece whose value equals the value of the piece before it is left out of the returned list). When a later order adds a switch, the script is run again; a table in a report is then old, so a later order reads the table from the script.
